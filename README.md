# food-ordering-go

Учебный сервис заказа еды на Go. Три самостоятельных HTTP-сервиса, каждый со своей базой SQLite. Между сервисами используется HTTP, общих таблиц нет.

## Сервисы

| Сервис | Порт | Ресурс |
| --- | --- | --- |
| Меню | 8081 | `/dishes` |
| Заказы | 8082 | `/orders` |
| Уведомления | 8083 | `/notifications` |

Каждый ресурс поддерживает GET и POST для коллекции, GET, PUT и DELETE по идентификатору. У заказа PUT меняет статус, у уведомления меняет текст. Проверка состояния доступна на `/health` каждого сервиса.

## Запуск

Нужны Docker и Docker Compose.

```sh
docker compose up --build -d --wait
docker compose ps
```

Создать заказ с блюдами из начального меню можно так.

```sh
curl -i http://localhost:8082/orders \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"dish_id":1,"quantity":2},{"dish_id":2,"quantity":1}]}'
curl http://localhost:8083/notifications
```

Сервис заказов получает названия и цены из меню, сохраняет заказ и отправляет запрос сервису уведомлений. Цены в API представлены целыми числами в полях `price_cents` и `total_cents`. Для суммы в рублях значение нужно разделить на 100. В примере итог равен 1050 рублям.

Остановка без удаления данных.

```sh
docker compose down
```

Базы хранятся в трех отдельных Docker volumes и сохраняются после остановки. Порты доступны только на локальном компьютере. При необходимости их можно изменить переменными `MENU_PORT`, `ORDER_PORT`, `NOTIFICATION_PORT`. Проект Compose называется `food-ordering-go`, поэтому его volumes отделены от учебной копии проекта.

## Проверка

Нужен Go 1.24 или новее.

```sh
go test -race -count=1 ./...
go vet ./...
go build ./...
```

Тесты используют временные базы и проверяют CRUD, сохранение данных, расчет заказа, переходы статусов, валидацию и ошибки соседних сервисов.

Для работающих контейнеров есть демонстрационный клиент.

```sh
go run ./demo
```

Клиент создает настоящий заказ и предполагает, что начальные блюда и их цены не изменены.

## Проверка отказов

Если меню недоступно, создание заказа возвращает HTTP 503 без сохранения нового заказа.

```sh
docker compose stop menu-service
go run ./demo -mode menu-outage
docker compose start menu-service
```

Если недоступны уведомления, заказ все равно сохраняется с HTTP 201, предупреждением и `notification_status=unconfirmed`.

```sh
docker compose stop notification-service
go run ./demo -mode notification-outage
docker compose start notification-service
```

Перед следующим сценарием нужно дождаться готовности запущенного сервиса. Статус `unconfirmed` означает отсутствие подтверждения. При тайм-ауте уведомление могло сохраниться, даже если ответ не был получен.

## Ограничения

Это локальный учебный пример без авторизации, оплаты и реальной отправки сообщений. Автоматические повторы и гарантированная доставка уведомлений не реализованы. Повторный POST заказа после потери ответа может создать дубликат. Сервис не предназначен для публикации в интернет без дополнительной защиты.
